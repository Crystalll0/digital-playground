# Hash Brown Catch · 分周交付包

仓库：https://github.com/sd5913/Hash-Brown-Catch · 看板：https://github.com/orgs/sd5913/projects/6 · 在线版（第 4 周起）：https://sd5913.github.io/Hash-Brown-Catch/

做好的游戏被拆成 5 个增量，每次导师评审对应一个，仓库一周一周长出来，每一步都能拿出来展示。

## 文件夹说明

| 路径 | 用途 |
|---|---|
| `weekN-日期/upload/` | 这周要放进仓库的文件（只有新增或改动的，按相同路径放） |
| `weekN-日期/指南-中文.md` | 要求对照表、本周改动、文件和负责人、提交、演示稿、要问的问题 |
| `weekN-日期/看板卡片-中文.md` | Group Project 2026 看板上要建的卡 |
| `weekN-日期/上传清单-中文.txt` | `upload/` 里的全部文件 |
| `weekN-日期/preview.png` | 这周结束时页面的样子 |
| `preview-builds/weekN-日期/` | 这周结束时仓库里应有的完整文件，双击 `start.command`（Windows 用 `start.bat`）运行。只用来检查，不要上传。 |
| `final-2026-12-06/` | 提交清单 |

每个文件旁边都有英文版（`GUIDE-EN.md`、`BOARD-CARDS-EN.md`、`UPLOAD-LIST-EN.txt`）。放进仓库的内容全部是英文。

## 仓库里怎么体现迭代
- `docs/changelog.md` 每周更新（最新的在上面），第 3 周起把每条反馈对应到它引起的改动。
- `docs/progress/` 每次见导师一份，写导师反馈、下周目标和负责人。
- 测试证据：`docs/test-log.md`（第 2 周）、`docs/playtest/`（第 3 周）、修复表（第 4 周）、最终测试（第 5 周）。
- `docs/assessment-map.md`（第 4 周）告诉评分老师每条要求在哪里能查到。

## 每周流程
1. 见导师前：把 `upload/` 传上去，每人用自己的账号小步提交；移动看板卡片。
2. 见导师时：按指南做 2–3 分钟演示，问准备好的问题。
3. 见导师后：在进度文件里填导师反馈、阻碍、下周目标；在导师评审卡上写评论；提交。

- 导师反馈、测试记录和 UX 测试结果必须真实，模板里这些地方是故意留空的。
